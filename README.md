# Assignment 5 — SPI DAC (MCP4921) on STM32L476RG

CPE 3160. Bare-metal, register-level driver for the Microchip **MCP4921** 12-bit SPI DAC
on an **STM32L476RG** (Nucleo-L476RG). No STM32 HAL is used for the DAC logic — the driver
talks to SPI1 and GPIOA directly through the CMSIS register definitions in `stm32l476xx.h`.

The program generates a square wave on the DAC output, alternating between ~1.0 V and ~2.0 V
with a 25% high duty cycle.

## Driver API (`DAC.h`)

| Function | Purpose |
|----------|---------|
| `DAC_init(void)` | Configure GPIOA + SPI1 (master, mode 0, MSB-first, 8-bit, BR /16) |
| `DAC_write(uint16_t code)` | Send one 16-bit MCP4921 command word with software chip-select framing |
| `DAC_volt_conv(uint32_t mv)` | Convert millivolts to a 12-bit DAC code (integer math, clamped to 4095) |
| `DAC_build_word(uint16_t code)` | Pure helper that builds the command word `0x3000 \| (code & 0x0FFF)` |

## Wiring (3.3 V only)

| STM32 Pin | Signal | MCP4921 Pin |
|-----------|--------|-------------|
| PA4 | Chip Select (GPIO output, active low) | 2 (CS) |
| PA5 | SPI1_SCK (AF5) | 3 (SCK) |
| PA7 | SPI1_MOSI (AF5) | 4 (SDI) |

MCP4921 power/reference: VDD (1) → 3.3 V, VREF (6) → 3.3 V, VSS (5) → GND,
LDAC (7) → GND, VOUTA (8) → scope/DMM. STM32 and MCP4921 must share a common ground.

> VREF must be 3.3 V — the driver hardcodes `DAC_VREF_MV = 3300`, so the output scaling
> depends on it.

## Building

The project builds with CMake + Ninja and the `arm-none-eabi` GCC toolchain (as set up by
STM32CubeIDE / STM32 for VS Code).

```sh
cmake --preset Debug
cmake --build --preset Debug
```

The firmware image is produced under `build/Debug/`.

## Notes

- The `build/` directory is git-ignored; it is regenerated by the build.
- SPI transaction (per `DAC_write`): CS low → high byte → low byte → wait TXE/BSY → CS high.
  The MCP4921 latches the new value on the CS rising edge (LDAC tied low).
